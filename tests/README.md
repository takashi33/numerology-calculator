# 計算ロジックの検証

`index.html` に書かれている計算処理そのものを取り出して、Node.js で自動テストする。
アプリは1枚のHTMLに全部入っている作りなので、テスト用にロジックを別ファイルへ
コピーすると「コピーの方だけ直してある／古いまま」が起きる。それを避けるため、
**テストは毎回 `index.html` から実物のコードを抜き出して実行する。**

## 使い方

```
cd tests
node extract.js   # index.html から計算コードを抜き出して extracted.js を作る
node test.js      # 検証を実行する
```

`extracted.js` は自動生成されるファイルなので、Git では追跡していない
（`node extract.js` を実行すればいつでも作り直せる）。

## 仕組み

- `extract.js` … `index.html` の該当行を切り出して、Nodeから読める形にする。
  切り出しは行番号で行っているため、`index.html` を編集すると範囲がずれる。
  **ずれたまま「別のコードを検証して全部通った」となるのが一番まずい**ので、
  期待する宣言がそろっているか・DOM参照が紛れ込んでいないかを毎回確かめ、
  ずれていればエラーで止まる。その場合は `extract.js` の `RANGES` を実際の
  行番号に合わせて直すこと。
- `test.js` … 検証本体。`spec.md` の記述から書き起こした**参照実装**を別に持ち、
  アプリの計算結果と突き合わせる。アプリのコードをそのまま写して比べても
  「同じ間違いをした2つを比べる」だけで意味がないため、あくまで仕様の文章を
  読んで独立に書いたものと比較している。

## 検証している内容

| 区分 | 内容 |
| --- | --- |
| 還元ルール | 1桁まで還元されること、11・22・33で止まること |
| ライフパス | `spec.md` の例（1978-12-14→33）、および **1900〜2025年の全日付（46,021件）** を参照実装と突き合わせ |
| 名前系 | デスティニー／ソウル／パーソナリティ／ライフレッスン／インテンシティ／マチュリティを手計算値と照合 |
| 名前系の整合 | 母音の合計＋子音の合計＝全体の合計（分割が漏れていないこと） |
| 変換表 | アルファベット26文字すべてが `spec.md` の対応表どおりか |
| 日付系 | バースデー、チャレンジ（基本3・4期）、ピナクル、年齢帯、パーソナルイヤー／マンス／デイ |
| ローマ字 | `spec.md` に載っている用例すべて（ヘボン式、促音、長音、ん→m、アポストロフィ、ヴ行、カタカナ正規化） |
| ローマ字の不変条件 | 同じカナから常に同じ綴りが出ること、変換済みの綴りを再変換しても変わらないこと |
| 通し | カナ入力 →ローマ字 →各ナンバー、までの一連の流れ |

## 注意

ここで検証しているのは**計算とローマ字変換だけ**で、画面表示（カードの見た目、
マスターナンバーの金の縁取り、モーダルの開閉など）は対象外。それらは引き続き
実機での確認が必要。
